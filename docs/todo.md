To-Do List
==========

Start by reading [the programming exercise](exercise.md). The goal is to
practice open-source collaboration, not only to improve the snake game.

Use the [issue catalog](issues.md) as the **single list of tasks** for this
exercise. Its IDs refer to catalog entries, not GitHub issue numbers. The
catalog also identifies estimated difficulty and prerequisites.

Your team must:

1. **Plan the work.** Create issues in **your own repository** for every
   **Critical** and **Required** entry in the catalog. Required entries
   include the configuration panel and the repository chores. Do not open
   these issues in the original KobraPy repository.
2. **Choose additional work.** Select **Wish** entries according to your
   team's interests and available time, or propose your own manageable
   improvements. Create issues for the work you choose.
3. **Describe each issue.** State the problem or proposed improvement, the
   expected result, how to verify it, and any dependencies. Create the
   initial issues **before changing the game**.
4. **Collaborate.** Develop each change in a dedicated branch, submit a
   pull request, and review and discuss it before merging. Coordinate work
   on dependent tasks and keep changes small and focused.
5. **Plan releases.** Follow the milestones and release workflow described
   in [the programming exercise](exercise.md).

Resolve every **Critical** and **Required** issue. **Wish** issues are optional,
not a second mandatory checklist. Update your plan as your team learns more
about the code.

Keep the code welcoming to newcomers: explain important mechanisms and
decisions in clear, human-oriented comments.
